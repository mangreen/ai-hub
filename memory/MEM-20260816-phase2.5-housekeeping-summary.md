## Details

**Skill 研究的實際限制：** GitHub 擋掉了對 `.agents/skills` 目錄頁的自動存取（robots.txt），
只有透過 `AGENTS.md` 裡的直接連結，才能真正讀到 3 份完整的 SKILL.md 內容
（`dsh-pre-push-checks`、`dsh-prose-standard`、`dsh-doc-standards`）。其餘 8 個 skill 只知道
檔名，沒有讀到內容，CLAUDE.md 2.1 節裡誠實列出這個限制，沒有假裝全部讀過。

**ASCII → Mermaid 的原因：** 第一版手畫 ASCII 圖，中英文混排（CJK 全形字元佔 2 個字元寬度）
導致人工對齊的框線全部歪掉。寫了一個 Python 腳本量測「視覺寬度」後證實真的對不齊，
後來你直接要求改成 Mermaid——這其實也更符合原始 v3.0 規範自己講的
「Use Mermaid for diagrams」，不是妥協。改用 Mermaid 後，另外裝了 `mermaid` + `jsdom`
寫了一個 `mermaid.parse()` 驗證腳本，兩張圖都是先驗證語法有效才寫進 `docs/architecture/`，
不是憑印象寫完就假設它是對的。

**文件審查抓到的過期內容：**
- `src/index.ts`、`src/plugins/channel/index.ts` 裡引用「Phase 0 的 `consumer.ts`/
  `event-demo.ts`」，但這兩個檔案已經被你刪除——改成指向 git branch
  `phase/0-environment-cordis-basics`。
- `src/plugins/chat/index.ts`、`src/plugins/agent/index.ts` 裡還寫著
  `TODO(Phase 2): createRoom, ...`，但 Phase 2 已經做完、`domain.ts` 已經有這些函式——
  改成準確描述現況（domain 邏輯存在且測試過，Service 本身還是空殼，等 Phase 4 接上持久化）。
- `agent/index.ts` 裡一句「README 範例2」講錯了來源——範例2其實在 `CLAUDE.md`，不在 `README.md`。

**`kernel-boot-check`（原名 `phase1-boot-check`）改名：** 這個驗證用的 plugin 原本用
Phase 編號命名，但它的用途（驗證五個 service 都掛載成功）不屬於任何特定 Phase，用 Phase
編號命名反而會在下一個 Phase 又過期。改成 evergreen 的名字，避免同樣的問題重演。

## When to Use
之後每次「大改動前的整理」（不一定要等到 Phase 邊界），都照這次的模式：
1. 先查證外部資料（skill 內容、API 簽章），不要憑印象。
2. 畫圖/寫文件前，能自動驗證正確性就自動驗證（Mermaid 語法、TypeScript 型別、測試），
   不要手工做容易出錯的事。
3. 審查 comment 時特別注意「這句話裡提到的東西還存在嗎」「這句話講的 Phase 狀態還準嗎」——
   過期的技術文件比沒有文件更危險，因為它看起來像真的。
